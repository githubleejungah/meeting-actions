### 1-2. 확장 원문 (2026-11-19)

> 네 합치고 해주세요

(사용자가 '채용공고 검토' 세션에서 "현장 이슈 접수 · 판정 시스템을 회의 자동화 앱에 합칠까"라는 물음에 한 답. 그 세션이 전했다.)

확장 내용(그 세션이 정리한 것, 사용자 원문 아님):

- 합친 제품의 한 줄: 회의와 현장에서 나온 일을 AI가 정리하고, 사람이 판정한다.
- 입력 두 갈래: ① 회의 녹음 텍스트 → 회의록 + 할 일 ② 현장 메시지(예: "3번 열에서 또 멈췄어요") · 사진 → 재현 조건 · 증상 · 기대 결과로 나누고 위험도를 '제안'. 판정과 위험도 확정은 사람이 한다.
- 근거 양식: 사용자의 PM 업무 샘플(2021~2022 컬티랩스에서 직접 만든 양식을 가상 예시로 다시 그림). 흐름 6단계 — 현장 접수 → 재현 조건 정리 → 우선순위 · 담당 → 일정 반영(시즌 마감에서 거꾸로) → 검증 · 판정 → 현장 확인 · 종결.
  - 이슈 관리표 칸: 번호 · 위험도(A 안전 · 작업 중단 / B 기능 저하 · 시즌 영향 / C 불편 · 표시 오류) · 재현 조건 · 증상 · 기대 결과 · 상태 · 목표일 · 판정 · 조치 · 지연 사유.
  - 우선순위표 칸: 순위 · 항목 · 근거 · 기준(안전 → 시즌 → 고객) · 난이도 · 예상(일) · 기획 담당 · 개발 담당 · 상태(진행 · 확인 중 · 완료 · 기획 전).
  - 판정 3가지: 반영 · 조건부 반영 · 보류.
- 확장 후보(범위는 인터뷰에서 정함): 인도된 장비 중 영향받는 대수 표시(소급 조치) · 주간 점검 보고서 자동 요약 · 지연 경보(목표일 1주 초과).
- 데이터는 모두 가상이다. 특정 회사의 제품 이름이나 내부 사정처럼 보이는 내용은 넣지 않는다.

## 2. 기존 도구 비교 (직접 만들 가치)

| 도구 | 비용 | 잘하는 일 | 못 하는 일 |
|---|---|---|---|
| 클로바노트(네이버) 개인 | 0원 · 월 300분(데이터 수집 동의 시 600분) · AI 요약 월 15회 | 한국어 받아쓰기 · 화자 구분 · 요약 · 할 일 뽑기 | 회의를 넘어 할 일을 한 대장에 쌓기 · 상태 · 지연 추적 · 미완료 알림 |
| Claude 대화창에 텍스트 붙여 넣기 | 쓰는 구독 안에서 추가 0원 | 회의록 · 할 일 정리 | 양식이 매번 달라짐 · 결과가 대화에만 남음 · 누적 관리 없음 |
| 회의 기록 서비스 + Claude 커넥터(Fireflies · Otter · Read AI 등) | 대부분 유료 · 영어 중심 | 화상회의 녹음 · 할 일 조회 | 대면 회의 · 한국어 품질 불확실 · 비용 |

판단(한 줄): 받아쓰기와 한 번 요약은 기존 무료 도구(유니브 · 클로바노트)로 충분하다. 직접 만들 가치는 **회의마다 나온 할 일을 한 대장에 쌓고, 상태 · 목표일 · 지연 사유를 다음 회의까지 이어 추적하는 부분**에만 있다.

근거: 클로바노트 무료 한도는 2026년 블로그 여러 곳에서 같은 숫자로 확인했다(공식 안내는 보지 않음). 받아쓰기는 사용자가 이미 쓰는 유니브로 하기로 해서(Q2) 이 한도는 앱과 관계없다.

## 3. 인터뷰 (Q/A)

진행: 질문 1개씩 → 사용자 답. "추천 수용"은 Claude 추천을 받아들인 것.

Q1: 누가, 어떤 회의에 쓰나? (사용자 · 권한)
A1: 혼자 내 PC에서 쓴다. 지금은 직접 만든 가상 회의 녹음으로 시연한다. 입사 뒤 실제 회의에도 그대로 쓴다. 로그인 · 공유는 없다. (추천 수용)

Q2: 녹음을 글로 바꾸는 일(STT, 음성 인식)은 무엇으로 하나?
A2: 유니브(Univ AI). 사용자가 지금 듣는 강의 텍스트를 이미 유니브로 만들어 쓰고 있어 텍스트 꺼내기는 된다. 앱은 도구와 상관없이 텍스트(붙여 넣기 또는 .txt)부터 받는다. 음성은 앱 밖에서 다룬다.

관찰 O1(2026-11-19, 사용자가 준 유니브 강의 텍스트 1개): UTF-8(BOM 있음) .txt. 모든 줄이 `[분:초] 문장` 또는 `[시:분:초] 문장` 형식이다(1,655줄 중 1줄 예외). **화자 표시는 없다.** 4시간 20분 강의가 1,655줄 · 약 120KB다. 내용은 저장소에 옮기지 않는다(강의 참석자 발화).

Q3: 녹음 동의는 어떻게 다루나?
A3: 앱에서는 다루지 않는다. 동의는 사용자가 회의 자리에서 직접 챙긴다.

Q4: 비용 상한은?
A4: 추가 0원. 지금 쓰는 Claude Code 구독 안에서 돌리는 명령(스킬)으로 만든다. Claude API 키는 쓰지 않는다. (추천 수용)
참고: API 방식이면 1시간 회의 1건에 Haiku 5.5 약 5원, Sonnet 5.5 약 100원(추론 I: 1시간 ≈ 1만5천 토큰 입력 · 3천 토큰 출력 가정, 요금표 2026-11 기준). 채택하지 않음.

Q5: Action Item 대장을 어디에 두나?
A5: 내 PC의 엑셀 파일 하나(.xlsx). 회의록 본문은 회의마다 파일 하나로 따로 둔다. (추천 수용)

Q6: Action Item 대장의 칸은?
A6: 10칸 — 번호 · 회의일 · 할 일 · 담당 · 목표일 · 상태(예정/진행/완료/보류) · 위험도(상/중/하) · 지연 사유 · 근거 시각(텍스트의 [분:초]) · 비고. 컬티랩스 이슈 관리표에서 가져오고, 버그용 '재현 경로'는 '근거 시각'으로 바꿨다. (추천 수용)
→ F6에서 바뀜: 위험도는 상/중/하 대신 A/B/C. '관련 이슈 번호' 칸을 더해 11칸.

Q7: 회의록 양식은?
A7: 5칸 — ① 머리(회의명 · 일시 · 참석자 · 작성자) ② 안건별 논의 요약 ③ 결정 사항 ④ Action Item(대장과 같은 칸) ⑤ 미결 사항 · 다음 회의. 회의마다 워드(.docx) 파일 하나. (추천 수용)

Q8: 다음 회의 전 미완료 할 일 알림은?
A8: 새 회의록을 만들 때 대장에서 '완료'가 아닌 항목을 꺼내 회의록 맨 앞 '지난 할 일 점검' 표로 넣는다. 목표일이 지난 항목을 위로 올린다. 점검만 하는 명령도 따로 둔다. 알림 서비스는 쓰지 않는다. (추천 수용)
→ F7에서 바뀜: 점검표 순서는 위험도 A → B → C, 같은 등급 안에서는 목표일 순. 목표일을 1주 넘긴 항목에는 '지연' 표시. 점검표에는 미완료 이슈도 함께 넣는다.

Q9: AI가 만든 할 일을 대장에 어떻게 넣나? (사람 개입 · 실패 동작)
A9: 담당 · 목표일을 발언에서 찾지 못하면 '미정'으로 둔다. 대장에 쓰기 전에 초안 표를 보여 주고, 사용자가 '반영'이라고 해야 엑셀에 더한다. 고칠 것은 사용자가 엑셀에서 직접 고친다(AI와 주고받기를 되풀이하지 않음). (추천 수용)

Q10: 개인정보 · 회사 기밀은?
A10: ① 공개 저장소에는 직접 만든 가상 회의만 올린다. ② 실제 회의 텍스트 · 회의록 · 대장은 저장소 밖 폴더에 두고 git에서 뺀다(강의 텍스트 포함). ③ 입사 후 회사 회의에 쓰기 전에 외부 AI 사용 가능 여부를 회사 보안 규정으로 먼저 확인한다. 이유: 정리 과정에서 텍스트가 Anthropic 서버로 간다. (추천 수용)

Q11: 얼마나 빨라야 하나? (성능)
A11: 1시간 회의 텍스트 → 회의록 워드 + 할 일 초안 표까지 5분 이내. 입력은 4시간 분량(약 120KB, O1)까지 받는다. 아직 재 본 적 없어 첫 시험에서 재고 고친다. (추천 수용)

Q12: 하지 않을 일은? (범위 밖)
A12: 6절 9가지. (추천 수용)

Q13: '잘 된다'의 기준은? (성공 지표)
A13: 이어지는 가상 회의 3건과 사람이 미리 적은 정답 할 일 목록으로 채점한다. 정답 할 일 90% 이상 찾기 · 지어낸 할 일 0건 · 담당 · 목표일 틀림 0건('미정'은 허용) · 1차 미완료 할 일이 2 · 3차 점검표에 100% 나오기. (추천 수용)

Q14: 시연용 입력은 어떻게 만드나? (입출력 예시)
A14: 3건 모두 Claude가 가상으로 만든다. 녹음은 하지 않는다. 주제는 '자율주행 트랙터 제품 개발 주간 회의'. 형식은 유니브와 같게([분:초] 문장, 화자 없음) 하고, 정답 할 일 목록도 함께 만든다. 실제 인식 오류 시험은 못 하므로 AS-6으로 보완한다.

### 3-2. 현장 이슈 인터뷰 (확장, 2026-11-19)

근거 양식: 사용자의 PM 업무 샘플(`긴트/_제출제외/build_sample.js`) 2 · 4 · 5쪽 — 이하 문서 근거 `D1`.

F1: 현장 메시지는 누가, 어떻게 넣나? (접수자 · 입력 수단)
A1: PM(사용자)이 농가 · 대리점 · 현장 담당에게 받은 메시지를 복사해 붙여 넣는다. 여러 건을 한 번에 넣을 수 있다. 현장 사람은 앱을 쓰지 않는다. (추천 수용)

F2: 현장 사진도 받나?
A2: 시제품은 텍스트만 받는다. 사진은 이슈 시트에 '첨부 파일 이름'만 적고 AI가 분석하지 않는다. 이유: 가상 현장 사진을 만들 수 없고, 실제 사진에는 위치 · 얼굴이 담길 수 있다. (추천 수용)

F3: AI가 위험도를 어떤 규칙으로 제안하나?
A3: D1 기준 A(안전 · 작업 중단) / B(기능 저하 · 시즌 영향) / C(불편 · 표시 오류) 중 하나를 제안하고 근거 문장을 붙인다. 사람 · 충돌 · 전복 · 비상정지 · 연기 같은 안전 낱말이 있으면 A. 두 등급 사이에서 애매하면 높은 쪽. (추천 수용)

F4: 판정 권한은?
A4: AI는 초안만 만든다(재현 조건 · 증상 · 기대 결과 나누기, 위험도 제안). 위험도 확정 · 판정(반영 / 조건부 반영 / 보류) · 상태 · 종결은 PM만 정한다. (추천 수용)

F5: 재현 조건이 빠진 메시지는?
A5: 빈 칸은 '미정'으로 두고, 현장에 되물을 질문을 최대 3개 만든다. 질문은 PM이 직접 보낸다. 답을 받으면 같은 이슈에 덧붙여 넣는다. (추천 수용)

F6: 할 일과 이슈를 어떤 표에 두나?
A6: 엑셀 파일 1개, 시트 2개. '할 일' 시트 11칸(Q6의 10칸 + 관련 이슈 번호). '이슈' 시트 16칸 — D1의 10칸(번호 · 위험도 · 재현 조건 · 증상 · 기대 결과 · 상태 · 목표일 · 판정 · 조치 · 지연 사유) + 접수일 · 접수 경로(농가 / 대리점 / 현장) · 원문 · 위험도 제안(근거) · 되물을 질문 · 첨부 파일 이름. 할 일의 위험도도 A/B/C로 통일한다. (추천 수용, Q6을 고침)

F7: 확장 후보 중 무엇을 넣나?
A7: 지연 경보(목표일 1주 초과 표시)와 우선순위 정렬(A → B → C, 같은 등급은 목표일 순)만 넣는다. 주간 점검 보고서 요약 · 소급 조치(영향 대수)는 범위 밖. (추천 수용, Q8을 고침)

F8: 시연용 가상 현장 메시지는?
A8: 12건(A 3 · B 5 · C 4). 재현 조건이 빠진 메시지 3건을 섞는다. 보낸 사람은 가상 농가 · 대리점 · 현장 담당. 가상 회의 3건과 이야기가 이어지게 해서, 회의에서 이슈를 판정하고 할 일이 나오는 흐름을 보여 준다. 제품 이름은 쓰지 않고 '자율주행 방제 장비' 같은 일반 명사만 쓴다. (추천 수용)

F9: 이슈 쪽 '잘 된다'의 기준은? (성공 지표)
A9: 가상 메시지 12건으로 채점한다. 위험도 제안이 정답과 같은 것 12건 중 10건 이상 · 정답 A를 B나 C로 낮게 제안 0건 · 원문에 없는 재현 조건 · 증상 지어냄 0건 · 조건이 빠진 3건 모두 '미정' + 되물을 질문 1~3개. (사용자가 "모두 추천대로"로 답함)

Q15: 다루지 못한 칸은 어떻게 하나?
A15: 사용자가 "모두다 추천대로 해서 만들어주세요"라고 답했다(2026-11-19). 아래 추천을 받아들인다.
- 회의명 · 일시 · 참석자는 실행할 때 사용자가 알려 준다. 없으면 '미정'.
- 이미 대장에 있는 행의 상태 · 판정 · 지연 사유는 사용자가 엑셀에서 직접 바꾼다. AI는 새 회의 · 메시지로 이 칸을 바꾸지 않는다. 예외는 F5의 '미정' 칸 채우기뿐이다.
- '반영'할 때마다 바꾸기 전 대장 사본 1개를 날짜 이름으로 저장한다(되돌리기용).
- 같은 문제로 보이는 새 메시지는 기존 이슈 번호를 '중복 의심'으로 표시만 한다. 합치기는 사람이 한다.
- 현장 메시지 보낸 사람의 이름 · 전화번호는 대장에 옮기지 않는다. 원문 칸에서도 가린다. 접수 경로(농가 / 대리점 / 현장)만 남긴다.
- 정답 목록(가상 회의 · 메시지)은 Claude가 만들고 사용자가 확인한다.
- 담당 '미정' 비율 상한은 두지 않고 첫 시험에서 관찰한다.

Q16: 서류에 넣을 호스팅은? (2026-11-19 추가)
A16: GitHub Pages 시연 페이지(0원). 가상 메시지 · 회의를 고르면 AI 초안(미리 돌린 결과라고 표시)이 나오고, 방문자가 위험도 확정 · 판정을 고르면 대장 · 점검표가 브라우저에서 같은 규칙으로 바뀐다. 실시간 AI 웹앱은 API 요금 · 키 관리 위험으로 기각. 내 PC 도구는 그대로 만든다. (추천 수용, 명세 수정안 AC-45~50 승인)

## 5. 수용 기준 (EARS)

작성 규칙

- 한 행 = 요구 1개 = 시험 1개 후보.
- 패턴: U 항상 · E When(하면) · S While(동안) · O Where(경우) · W If…then(만약).
- 분류: SFR 기능 · DAR 데이터 · PER 성능 · SECR 보안 · CONR 제약.
- 근거: `Qn` · `Fn` 인터뷰 답 · `O1` 관찰(유니브 강의 텍스트) · `D1` 문서(PM 업무 샘플) · `I` 추론 · `AS-n` 가정.
- 주어 "the system"은 Claude Code 안에서 돌리는 회의록 · 이슈 명령(스킬)과 그 보조 스크립트 묶음이다.
- "닫히지 않은 항목"은 상태가 '완료'(할 일) 또는 '종결'(이슈)이 아닌 항목이다.
