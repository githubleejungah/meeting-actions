## 1. 정본 표

정본은 가장 믿을 원본이다. 사본은 정본에서 만들어지므로, 어긋나면 정본을 믿고 사본을 다시 만든다.

| 데이터 | 정본 | 주인(고칠 수 있는 사람) | 사본 |
|---|---|---|---|
| 회의 텍스트 | 유니브에서 내보낸 .txt(데이터 폴더 `inputs/`) | 사용자 | 초안 JSON의 근거 인용 |
| 현장 메시지 | 가린 뒤의 텍스트(`inputs/`). 가리기 전 원본은 저장하지 않는다 | 사용자 | 이슈 시트 '원문' 칸 · 초안 인용 |
| 할 일 · 이슈의 현재 값 | 대장 엑셀 `ledger.xlsx` | 사람 칸은 사용자, 새 행 추가는 `apply.py` | 회의록 워드의 Action Item · 점검표, 백업 |
| 초안 | `drafts/*.json` | Claude가 쓰고 `validate.py`가 검사 | 반영 뒤 대장 행 |
| 회의록 | `minutes/*.docx` | 처음엔 `apply.py`가 만들고, 그 뒤엔 사용자 | — |
| 백업 | `backups/ledger_YYYYMMDD-HHMMSS.xlsx` | `apply.py`(쓰기만, 지우지 않음) | — |
| 규칙(안전 낱말 · 값 목록 · 지연 일수) | 저장소 `src/rules.json` | 사용자 | 스킬 설명문 |
| 가상 데이터 · 정답 | 저장소 `samples/` | Claude가 만들고 사용자가 확인 | 채점 결과 |
| 데이터 폴더 경로 | `config.json`(git 제외) | 사용자 | — |
| 시연 데이터 | `site/demo-data.json`(가상 입력 + 미리 돌린 검사 통과 초안) | 내 PC 도구 실행 결과 | 시연 페이지 화면 |

## 3. 대장 `ledger.xlsx`

쓰는 쪽 범례: **AI** = Claude 초안(검사 통과 뒤 반영) · **시스템** = 스크립트 고정 규칙 · **사람** = 사용자가 엑셀에서 직접.
`apply.py`는 새 행만 추가한다. 이미 있는 행의 **사람** 칸은 바꾸지 않는다(AC-12). 예외는 이슈의 '미정' 칸 채우기(AC-33).

## 4. 초안 JSON

Claude가 쓰고 `validate.py`가 검사한다. 모든 AI 값에는 원문 인용(`quote`)이 붙는다. 인용이 원문에 글자 그대로 없으면 검사에서 떨어진다(지어낸 값 막기).

### 4-1. 회의 초안 `drafts/meeting_YYYYMMDD-HHMMSS.json`

```json
{
  "kind": "meeting",
  "source_file": "inputs/meeting_20261120.txt",
  "header": {"name": "미정", "date": "미정", "attendees": "미정", "author": "미정"},
  "agenda": [{"title": "안건 제목", "summary": "논의 요약", "quotes": ["[12:05]"]}],
  "decisions": [{"text": "결정 사항", "quotes": ["[15:40]"]}],
  "todos": [{
    "task": "할 일",
    "owner": "미정",
    "due": "미정",
    "evidence_times": ["[15:42]"],
    "quote": "원문 문장 일부",
    "related_issue": "I-003",
    "duplicate_of": null
  }],
  "open_items": [{"text": "미결 사항", "quotes": ["[40:10]"]}],
  "next_meeting": "미정"
}
```

### 4-2. 이슈 초안 `drafts/issue_YYYYMMDD-HHMMSS.json`

```json
{
  "kind": "issue",
  "received_date": "2026-11-20",
  "items": [{
    "msg_id": "M04",
    "received_date": "2026-11-14",
    "masked_text": "가린 원문 전체",
    "route": "농가",
    "condition": {"value": "미정", "quote": null},
    "symptom": {"value": "멈춘 뒤 다시 출발하지 않음", "quote": "또 멈췄어요"},
    "expected": {"value": "미정", "quote": null},
    "risk_suggestion": {"grade": "B", "quote": "또 멈췄어요", "safety_word": null},
    "questions": ["멈춘 시각이 언제였나요?", "그때 화면에 뜬 말이 있었나요?", "날씨는 어땠나요?"],
    "attachments": [],
    "duplicate_of": ["I-002"]
  }],
  "append_to": null
}
```

항목의 `received_date`(메시지 머리줄)가 정본이고, 맨 위 `received_date`는 머리줄이 없을 때의 기본값이다. `quote`는 문자열 하나 또는 조각 목록이며, 모든 조각이 원문에 있어야 한다. 재현 조건은 다시 해 볼 수 있을 만큼(장소 + 시각 · 날씨 · 조작 등) 있을 때만 채운다.

`append_to`에 이슈 번호가 있으면 되물은 답 덧붙이기다. 이때는 그 이슈의 '미정' 칸만 채운다(AC-33).

### 4-3. 검사 규칙 (`validate.py`)

| 검사 | 떨어지는 경우 | AC |
|---|---|---|
| 근거 시각 | 할 일에 `evidence_times`가 없거나, 그 시각 줄이 원문에 없음 | AC-05 · 06 |
| 인용 | `quote`가 원문(가린 원문)에 글자 그대로 없음. 값이 '미정'이면 인용 없음 허용 | AC-06 · 43 |
| 사람 칸 | 초안에 위험도 확정 · 판정 · 상태 · 조치 · 지연 사유 · 종결 값이 있음 | AC-31 |
| 값 목록 | 위험도가 A/B/C 밖, 접수 경로가 4가지 밖, 날짜 형식이 틀림 | AC-35 |
| 질문 수 | '미정' 칸이 있는데 질문이 0개, 또는 4개 이상 | AC-32 |
| 안전 낱말 | 원문에 안전 낱말이 있는데 제안이 A가 아님 → 검사가 A로 올리고 이유를 남김 | AC-29 |
| 관련 이슈 | `related_issue` · `duplicate_of`가 대장에 없는 번호 | F6 |
| 개인정보 | 가린 원문에 전화번호 형태가 남음 | AC-38 |

## 5. 규칙 파일 `src/rules.json`

```json
{
  "safety_words": ["사람", "충돌", "전복", "비상정지", "연기"],
  "risk_order": ["A", "B", "C", ""],
  "delay_days": 7,
  "todo_status": ["예정", "진행", "완료", "보류"],
  "issue_status": ["접수", "확인 중", "수정 중", "수정 완료", "추후 수정", "종결"],
  "verdicts": ["반영", "조건부 반영", "보류"],
  "routes": ["농가", "대리점", "현장", "미정"],
  "max_questions": 3,
  "max_input_bytes": 125000
}
```

`max_input_bytes`는 4시간 분량(O1: 약 120KB)에 여유를 둔 값이다(AC-24). 안전 낱말은 시작값이다(AS-9).

## 6. 가리기 규칙 (`mask.py`, AC-38)

| 대상 | 규칙 | 바꾼 모양 |
|---|---|---|
| 전화번호 | `01x-xxxx-xxxx`, 붙여 쓴 11자리, 지역번호 형태 | `[전화번호]` |
| 사람 이름 | "○○○ 씨 · 님 · 사장님 · 대표" 앞 2~4글자, 메시지 첫머리 "저 ○○○인데요" | `[이름]` |

이름은 규칙으로 다 잡지 못할 수 있다. 그래서 Claude 초안에서도 이름을 쓰지 않게 하고, 가상 메시지 12건 중 이름 · 번호를 넣은 시험 메시지로 확인한다.

## 7. 가상 데이터 `samples/`

| 파일 | 내용 | 근거 |
|---|---|---|
| `meetings/m1.txt` ~ `m3.txt` | 자율주행 방제 장비 개발 주간 회의 3건, 유니브 형식(`[분:초]`, 화자 없음), 인식 오류 일부 섞음 | Q14 · AS-6 |
| `messages/batch1.txt` ~ | 현장 메시지 12건(A 3 · B 5 · C 4), 조건 빠진 3건, 이름 · 번호 든 시험 1건, 중복 1쌍 | F8 · AC-38 · 39 |
| `answers/meetings.json` | 회의별 정답 할 일(할 일 · 담당 · 목표일 · 근거 시각) | Q13 |
| `answers/messages.json` | 메시지별 정답 위험도 · 재현 조건 · 증상 · 기대 결과 · 빠진 칸 | F9 |

제품 이름은 가상 이름도 쓰지 않는다. 특정 회사 내부 사정처럼 보이는 내용은 넣지 않는다.
