# 현장 이슈 접수

규칙의 정본: `docs/requirements.md` 5-2절 · `docs/flows.md` 2 · 3절. 명령은 저장소 맨 위에서 `.venv/Scripts/python -m ...`.

## 0. 입력 모양
메시지마다 머리줄 `### <번호> | <접수일> | <농가|대리점|현장>` + 본문. 머리줄이 없으면 접수일은 오늘, 경로는 사용자가 말한 값, 말하지 않았으면 `미정`. 사진은 사용자가 알려 준 **파일 이름만** 받는다(AC-37).
`/issue I-003` 처럼 이슈 번호가 붙거나, 머리줄이 `### <번호> 답 | <날짜> | <경로> | <이슈 번호>`(4칸)이면 3절(덧붙이기)로 간다.

## 1. 가리기 먼저
- 입력을 데이터 폴더 `inputs/`에 저장한 뒤 `python -m src.mask <파일> -o <파일>.masked.txt`. 이후에는 **가린 글만** 본다. 초안에 사람 이름 · 전화번호를 쓰지 않는다(AC-38).
- `python -m src.checklist` 로 열린 이슈(번호 · 증상)를 본다(중복 의심용).

## 2. 초안 JSON → 데이터 폴더 `drafts/issue_YYYYMMDD-HHMMSS.json`
모양은 `docs/data-model.md` 4-2절. 메시지 1건 = item 1개(AC-27). 지킬 것:
- `masked_text`: 그 메시지의 가린 본문 그대로(손으로 옮기지 말고 가린 파일에서 잘라 넣는다). `msg_id` · `received_date` · `route`는 머리줄 값이 정본이다. 맨 위 `received_date`는 머리줄이 없을 때의 기본값.
- `condition`(재현 조건) · `symptom`(무엇이 일어났나) · `expected`(어떻게 돼야 하나): 원문에 있을 때만 쓰고 `quote`에 원문 일부를 **글자 그대로** 붙인다. 흩어져 있으면 `quote`를 조각 목록(`["…", "…"]`)으로. 없으면 `{"value": "미정", "quote": null}`(AC-43).
  - 재현 조건은 개발팀이 **다시 해 볼 수 있을 만큼** 있을 때만 쓴다: 장소 · 대상에 더해 시각 · 날씨 · 땅 상태 · 하던 조작 · 데이터 조건 중 하나 이상. "3번 열에서"처럼 장소만 있으면 `미정`으로 두고 질문으로 묻는다(장소는 원문 칸에 남는다).
  - 기대 결과는 원문에 바라는 상태("~해야 · ~돼야 · ~보여야")나 이전 정상 상태("작년엔 ~했다")가 있을 때만 쓴다.
- 빠진 칸이 있으면 현장에 되물을 질문을 **1~3개**(AC-32). 짧고 답하기 쉽게(시각 · 날씨 · 화면에 뜬 말 · 그때 하던 조작). 빠진 칸이 없으면 `questions: []`.
- `risk_suggestion`: A · B · C 중 하나 + 근거 `quote`(위험도 판단의 핵심이 된 증상 문장, AC-28). `safety_word`는 비워 둔다(검사 스크립트가 채운다). 기준(PM 업무 샘플):
  - A 안전 · 작업 중단 위험: 사람 근처 · 충돌 · 전복 · 연기 · 비상정지 문제. 예) "회전 뒤 경로를 크게 벗어남"
  - B 기능 저하 · 시즌 영향: 작업은 되지만 품질 · 시간이 나빠짐, 멈춘 뒤 재출발 안 함. 예) "멈춘 뒤 다시 출발하지 않음"
  - C 불편 · 표시 오류: 작업 결과에 영향 없는 화면 · 기록 · 문구 문제. 예) "날짜 칸이 숫자로 보임"
  - 두 등급 사이에서 애매하면 **높은 쪽**(AC-30). 안전 낱말은 검사 스크립트가 A로 올린다(AC-29).
  - 이것은 '제안'이다. 위험도 확정 · 판정 · 상태는 쓰지 않는다(AC-31).
- `duplicate_of`: 열린 이슈와 같은 문제로 보이면 그 번호(표현이 달라도: "3번 열" = "세 번째 줄"). 합치지 않는다(AC-39).

## 3. 덧붙이기 (`/issue I-003` + 현장 답)
- 1절처럼 가린 뒤, `append_to: "I-003"`인 초안에 그 이슈의 **'미정' 칸만** 채운다. 새 질문은 만들지 않는다(flows 3절).

## 4. 검사 → 보여 주기 → 반영
- `python -m src.validate <초안>` → 탈락 이유를 보고 **한 번만** 고쳐 다시 검사. 두 번째 탈락은 그대로 둔다.
- 표를 보여 주며 "위험도는 제안입니다. 확정 · 판정은 엑셀에서 직접 해 주세요. ‘반영’이라고 하시면 대장에 넣습니다."라고 한 번 말하고 기다린다.
- '반영' → `python -m src.apply <초안>.checked.json`. 종료 코드 3이면 안내를 한 번 전하고 끝낸다(AC-25). '반영'이 아니면 아무것도 쓰지 않는다(AC-20).
