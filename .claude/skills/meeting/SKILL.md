# 회의 정리

규칙의 정본: `docs/requirements.md`(AC 번호) · `docs/flows.md` 1절. 아래 순서를 그대로 따른다.
명령은 저장소 맨 위에서 `.venv/Scripts/python -m ...`으로 돌린다. 데이터 폴더는 `python -c "from src.common import data_dir; print(data_dir())"`로 확인한다.

## 1. 입력 저장 · 형식 검사
1. 텍스트를 데이터 폴더 `inputs/meeting_<회의일 또는 지금 시각>.txt`로 저장한다(파일을 받았으면 복사). 저장소 안에는 저장하지 않는다(AC-10).
2. `python -m src.parse <그 파일>` → `ok`가 false면 `message`를 그대로 전하고 **끝낸다**(AC-22 · 24).

## 2. 머리 정보
- 회의명 · 일시 · 참석자 · 작성자는 **사용자가 말한 값만 글자 그대로** 쓴다(AC-15). 말하지 않은 칸은 `미정`(AC-16). 따로 묻지 않는다.

## 3. 열린 이슈 보기
- `python -m src.checklist --today <회의일>` 로 닫히지 않은 할 일 · 이슈를 본다. 관련 이슈 번호를 붙일 때만 쓴다.

## 4. 초안 JSON 쓰기 → 데이터 폴더 `drafts/meeting_<회의일>.json`
모양은 `docs/data-model.md` 4-1절. 지킬 것:
- **할 일**은 "누가 무엇을 (언제까지) 하기로 했다"는 말만. 결정 · 보류 · 미결 · 지난 할 일 경과 보고는 할 일이 아니다(각각 decisions · open_items).
- `owner`: 원문에 나온 이름을 그대로(예: "지훈"). "제가 · 저희 · 각자"처럼 누군지 알 수 없으면 `미정`. 이름을 지어내지 않는다(AC-17).
- `due`: 회의일 기준으로 "이번 주 금요일 · 다음 주 목요일 · 내일 · 수요일"을 `YYYY-MM-DD`로 바꾼다. 날짜 말이 없거나 회의일을 모르면 `미정`(AC-18). 주는 월요일에 시작한다.
- `evidence_times`: 할 일을 맡기거나 받은 줄의 시각을 원문 그대로(`[1:41]`). 1개 이상(AC-05).
- `quote`: 그 줄의 원문 일부를 **한 글자도 고치지 않고** 복사(AC-06).
- `related_issue`: 열린 이슈 중 같은 문제면 그 번호, 아니면 null.
- 사람 칸(status · risk · verdict · action · delay_reason · note)은 쓰지 않는다(AC-31).
- agenda · decisions · open_items에도 `quotes`(근거 시각)를 단다. 할 일이 없으면 `todos: []`(AC-23).

## 5. 검사
- `python -m src.validate <초안>` → 검사 탈락이 있으면 이유를 보고 **한 번만** 고쳐 써서 다시 검사한다. 두 번째에도 떨어진 항목은 그대로 '검사 탈락'으로 남긴다(flows 1절).

## 6. 보여 주고 기다리기
- validate가 낸 표를 그대로 보여 주고 "‘반영’이라고 하시면 대장에 넣고 회의록 워드를 만듭니다."라고 한 번 말한다(AC-11). 사용자 답을 기다린다.
- '반영'이 아니면 아무것도 쓰지 않고 끝낸다(AC-20). 고칠 것은 엑셀에서 직접 고치거나 다시 실행하도록 안내한다.

## 7. 반영
- `python -m src.apply <초안>.checked.json --today <회의일>` → 결과(추가 번호 · 회의록 위치 · 백업)를 전한다.
- 종료 코드 3(대장이 열려 있음)이면 안내 문장을 그대로 한 번 전하고 끝낸다. 다시 시도하지 않는다(AC-25).
